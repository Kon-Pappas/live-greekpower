# Decisions log

Format: **what** · *why* · alternatives rejected. The log starts on 18 October 2026, the day the alignment with the other hub dashboards began. Items marked *(planned)* are decided but not yet in the code. Newest decisions last.

| # | Decision | Why / what was rejected |
|---|---|---|
| D01 | The page moves to **Tailwind + Chart.js**; Bootstrap and ECharts are removed *(planned, phase 3)* | Same stack as BESS, Gas-Power and Flows: one way of building charts and layouts to maintain. Bootstrap was used only for a grid and one `form-select`, and it clashes with Tailwind. Rejected: keeping ECharts (more powerful, but a third stack in the family). |
| D02 | Scheduling only through the external **cron-job.org**: scrape every hour at :05; X-Ray at 10:15 (RESMV file) with a 13:30 fallback. The workflows have no `schedule:` block | cron-job.org is punctual. GitHub's own cron fires late (5–20 min) and, next to the external trigger, ran the scrape twice an hour. |
| D03 | One concurrency group **per workflow** (`scrape-live`, `xray-backfill`), `cancel-in-progress: false` | Stops two runs of the same workflow from overlapping. Rejected: one shared group, because GitHub cancels a *pending* run when a newer one is queued in the same group, so an hourly scrape could cancel a waiting X-Ray. |
| D04 | Both workflows push with `git pull --rebase` and up to 3 retries | The two workflows commit different files, so the rebase is always clean; the retry covers a push that lands in between. Before, only X-Ray rebased and the scrape could fail its push. |
| D05 | Files a script **rewrites** (`live_data.json`, `records.json`; since D14 also `xray_data.json` and `entsoe_ref.json` in their builders) are read strictly: if one exists but cannot be parsed, the run stops with exit 1 and writes nothing. In the scraper, `xray_data.json` is only read and is read leniently. All writes are atomic (temporary file, then rename) | Before, a corrupt `records.json` was silently ignored and the records were rebuilt from the 30-day live window, overwriting the history. A test on 18 Oct 2026 lost 4 of 42 record positions, a number that grows every month. A failed run leaves the last good file in the repository and GitHub sends an e-mail. |
| D06 | The Live tab's hour selector lists only hours with generation or demand above zero | ADMIE publishes the day-ahead price for the whole day in advance, so the file holds records for hours that have not happened yet; selecting one showed empty charts. |
| D07 | The Live status pill measures the time since the **end of the latest data hour**, in Athens time whatever the visitor's time zone: up to 75 min *Live*, up to 3 h *Delayed*, beyond that *Stale* | With the scrape at :05 and ADMIE's lag of about 5 min, the latest hour is normally 5–65 min old; 75 min means at least one run was missed. Rejected: the fetch timestamp, because it is refreshed on every run even when ADMIE has no new hour. |
| D08 | Commit messages carry Athens time | The runner's clock is UTC, so commits read "03:05" for a 06:05 run. |
| D09 | The accent colour is **platinum** (`#cbd5e1`, with 200/300/500 tints), defined in one place at the top of `index.html` (`window.ACCENT`, used by Tailwind as `acc-*` and by the charts) | Follows BigHydro D23, one accent per dashboard; emerald, blue, cyan and violet are taken. Chosen on 18 Oct 2026 from four restrained options (platinum, claret, champagne, petrol) after amber was rejected: in energy charts yellow always means imports. Platinum carries no energy meaning, keeps the page strictly professional and, being neutral among four saturated siblings, sets the live page apart on the hub. Rejected: amber/champagne (read as imports), claret (close to the red of exports), petrol (close to BESS emerald on the hub), fuchsia/rose/teal (too saturated or too close to siblings). |
| D10 | English by default with a Greek toggle; the choice is stored under the shared key `kp_lang` *(planned, phase 3)* | Follows BigHydro D24: all dashboards share one origin, so a visitor's language follows them across the hub. |
| D11 | Documentation starts lean: `DECISIONS`, `KNOWN_ISSUES` and `ROADMAP` now; `ARCHITECTURE`, `DATA_DICTIONARY` and `METHODS` after phase 2 | The data contract changes in phase 2, so describing it now would mean rewriting it. `METHODS` will also be the source text of the methodology modal. |
| D12 | No daylight-saving changes before 25 Oct 2026 | The owner is away that day. The day is recoverable: a manual run with start and end date re-fetches it, and records keep the maximum value, so a corrected, higher total replaces a low one. See K01. |
| D13 | Scope: this repository is handled in its own threads; the other dashboards and the shared shell are separate work | Keeps context clean, as for BigHydro (D21). |
| D14 | The JSON helpers live in one shared module, `jsonio.py` (strict load, lenient load, atomic write), used by `scraper.py`, `xray_builder.py` and `entsoe_builder.py`; the two builders now load their history strictly | The builders had the same silent `except: pass` as the records. A test on 18 Oct 2026 with a corrupt `xray_data.json` (or `entsoe_ref.json`) left 48 of 4,776 hours: the history since 1 Apr 2026, which exists nowhere else, would have been replaced by the last two days. One module keeps the rule in one place. |
| D15 | **Data contract v1**: one file per day and per source (`data/live/`, `data/xray/`, `data/entsoe/`), plus `manifest.json`; each file has exactly one writer (live, records and manifest: scraper; xray: xray_builder; entsoe: entsoe_builder). Logic in `contract.py` | Small downloads (one day is a few KB instead of 3.4 MB, K04), small git diffs, the live history is no longer cut at 30 days. One writer per file keeps D04 valid. Rejected: one shared file per day, because scrape and X-Ray both write the day before yesterday and would conflict. |
| D16 | Python computes, the page only draws: demand, totals per day, flags and UCE are in the files; keys are English, ADMIE's Greek names stay only inside the scraper's mapping | One definition of every number; the records use exactly what the visitor sees. |
| D17 | `imports`/`exports` are ADMIE's official totals (`TOTAL IMPORTS`/`TOTAL EXPORTS`); the per-country flows are a breakdown, with `flows_match` per hour; `demand` is ADMIE's `TOTAL_LOAD`, with `balance_ok` checking it against generation + imports − exports + discharge − charge − pumping | On 726 unique hours (18 Sep–18 Oct 2026) the identity holds in every hour and the countries add up to the totals in every hour. |
| D18 | UCE is stored **with its sign** and computed by `xray_builder` from the live day file of the same date (read only); `phys_clean` keeps the current definition (other_res excluded) | 34 negative hours on 9 days were hidden as 0 (K03). The live day exists when X-Ray runs (D-1, D-2). |
| D19 | `records.json` keeps its format but is **recomputed from the whole history** on every run; entries dated before the first available day of their source are kept as they are ("legacy") | A downward revision by ADMIE now corrects the record (K05). Test on 18 Oct 2026: all 14 categories identical to the previous file. |
| D20 | Transition with **double writing**: the scripts keep writing the old files, so the current page works unchanged; the history is converted once by `migrate_v2.py` (workflow *Migrate to v2*, manual, safe to re-run); the old files are removed after the phase-3 page goes live | No interruption for visitors; no snapshot of the data shipped in a zip (the conversion runs on the repository's current data). |
| D21 | The phase-3 page: Tailwind (play CDN, pinned to 3.4.17, accent palette via `tailwind.config`) + Chart.js 4.5.1 (pinned); house shell (breadcrumb, Last/Next update, picker, Methodology, GR \| EN with `kp_lang`, step-by-step loading overlay, modal with fixed header/footer); reads only the v1 files; `css/styles.css` is no longer used | Implements D01, D09, D10. Pinned versions so a library release cannot change the page overnight. |
| D22 | Imports keep the conventional yellow (`#ffc000`); status pill: *Live* green, *Delayed* orange, *Stale data* red, *Past hour / Past day / Ex-post data* neutral grey; record ranks #1 in the accent, #2–#3 in greys | Energy colour conventions win over decoration; the accent stays free of meaning (D09). |
| D23 | Hours are labelled by their start (`00–01` … `23–24`, axis ticks `00` … `23`) | Resolves K09; matches how readers count hours. |
| D24 | The daily leaderboard is split into *Where the energy came from* (sources, imports, BESS discharge) and *Where it went* (demand, exports, BESS charge, pumping), each with its share | Resolves K06. Moved from phase 4 to phase 3 because the view was being rebuilt anyway. |
| D25 | The page checks `manifest.json` every 5 minutes and loads a new hour when one appears; the status pill is re-evaluated every minute | A tab left open stays current. |
| D26 | GitHub Actions: `actions/checkout@v5`, `actions/setup-python@v6` | The v4/v5 releases target Node.js 20, which GitHub is retiring (warning in the runs of 18 Oct 2026). |
| D27 | Hourly charts use our own HTML tooltips (Chart.js `external`): header *Hour 10–11* on the left in the accent, *MCP* on the right in the price colour (shown even at 0 €/MWh, which is market information); rows grouped by dashed rules; **rows whose value is zero or rounds to zero are not shown**, and an empty group leaves no rule. Also on the flows chart and the ADMIE vs ENTSO-E chart | The owner's reading order from his earlier ECharts tooltips; zero rows add noise (owner's request, 18 Oct 2026). |
| D28 | Fixed stacking and tooltip orders (owner's specification, 18 Oct 2026). **Daily**, bars bottom → top: exports, BESS charge, pumping \| lignite, gas, imports, BESS discharge, RES, hydro; tooltip top → bottom: hydro, RES, BESS discharge, imports, gas, lignite · demand (bold), pumping, BESS charge, exports. **Clean energy**, bars bottom → top: biomass, small hydro, cogeneration, UCE, solar, large hydro, wind; tooltip top → bottom: wind, large hydro, solar · UCE · cogeneration, small hydro, biomass · total clean energy | The tooltip reads the bar from the top down. Cogeneration (not in the owner's tooltip list) and the total line (from his reference image) are kept; each can be removed with one line. |
| D29 | **Phase 3b** (18 Oct 2026): the old aggregate files are retired. The scraper's merge (keep the previous value when ADMIE returns an empty one) now uses `data/live_raw.json`, which holds only yesterday and today; on its first run it seeds from the old `live_data.json` and deletes it. `xray_builder` and `entsoe_builder` write only day files and delete `xray_data.json` / `entsoe_ref.json`. Workflows commit with `git add -A data`, so deletions are recorded. `migrate_v2.py`, its workflow and `css/` are removed by hand | The page reads only the v1 files since D21; the merge never needed more than two days. Tested: the scraper's day files are identical before and after, and the deletion is staged. |
| D30 | **Cogeneration (CHP) is not clean and is removed from both sides of UCE.** Physical clean = large hydro + small hydro + solar + wind + biomass (SCADA + RESMV); live clean = live RES + hydro − cogeneration. On the Live and Daily tabs "RES" keeps ADMIE's meaning and is labelled *RES (incl. CHP)* | Checked on 17 Oct 2026: live lignite, gas and hydro equal SCADA exactly; live RES = SCADA `TOTAL RES` (which contains the four CG units) + a distribution estimate. ADMIE therefore counts CHP (≈1.4 GWh/day: 835 SCADA + 583 RESMV) inside RES. Removing it from one side only would inflate UCE by that amount; removing it from both leaves UCE unchanged (tested: 720/720 hours identical). Supersedes the one-sided removal discussed earlier the same day. |
| D31 | Backfill of live history through a manual workflow (`backfill.yml`): chunks of 15 days, a pause between days (default 5 s) and between chunks (default 60 s), a commit after every chunk; the scraper in historical mode does not touch `live_raw.json`, and with `SKIP_DERIVED=1` it does not write `records.json` or `manifest.json` (the next hourly scrape rebuilds both) | Polite to ADMIE's server; progress is kept if a run stops; one writer per file (D15) keeps the hourly scrape and the backfill from conflicting. |
| D32 | `recompute_uce.py` recomputes physical clean, live clean and UCE in the stored X-Ray files from local files only (no download); the backfill workflow runs it over the whole X-Ray history | Days written before their live data existed get their UCE; a change of definition (D30) reaches every day without fetching 200 SCADA/RESMV files again. |
