# Decisions log

Format: **what** · *why* · alternatives rejected. The log starts on 18 October 2026, the day the alignment with the other hub dashboards began. Items marked *(planned)* are decided but not yet in the code. Newest decisions last.

| # | Decision | Why / what was rejected |
|---|---|---|
| D01 | The page moves to **Tailwind + Chart.js**; Bootstrap and ECharts are removed *(planned, phase 3)* | Same stack as BESS, Gas-Power and Flows: one way of building charts and layouts to maintain. Bootstrap was used only for a grid and one `form-select`, and it clashes with Tailwind. Rejected: keeping ECharts (more powerful, but a third stack in the family). |
| D02 | Scheduling only through the external **cron-job.org**: scrape every hour at :05; X-Ray at 10:15 (RESMV file) with a 13:30 fallback. The workflows have no `schedule:` block | cron-job.org is punctual. GitHub's own cron fires late (5–20 min) and, next to the external trigger, ran the scrape twice an hour. |
| D03 | One concurrency group **per workflow** (`scrape-live`, `xray-backfill`), `cancel-in-progress: false` | Stops two runs of the same workflow from overlapping. Rejected: one shared group, because GitHub cancels a *pending* run when a newer one is queued in the same group, so an hourly scrape could cancel a waiting X-Ray. |
| D04 | Both workflows push with `git pull --rebase` and up to 3 retries | The two workflows commit different files, so the rebase is always clean; the retry covers a push that lands in between. Before, only X-Ray rebased and the scrape could fail its push. |
| D05 | Files the scraper **rewrites** (`live_data.json`, `records.json`) are read strictly: if one exists but cannot be parsed, the run stops with exit 1 and writes nothing. `xray_data.json` is only read and is read leniently. All writes are atomic (temporary file, then rename) | Before, a corrupt `records.json` was silently ignored and the records were rebuilt from the 30-day live window, overwriting the history. A test on 18 Oct 2026 lost 4 of 42 record positions, a number that grows every month. A failed run leaves the last good file in the repository and GitHub sends an e-mail. |
| D06 | The Live tab's hour selector lists only hours with generation or demand above zero | ADMIE publishes the day-ahead price for the whole day in advance, so the file holds records for hours that have not happened yet; selecting one showed empty charts. |
| D07 | The Live status pill measures the time since the **end of the latest data hour**, in Athens time whatever the visitor's time zone: up to 75 min *Live*, up to 3 h *Delayed*, beyond that *Stale* | With the scrape at :05 and ADMIE's lag of about 5 min, the latest hour is normally 5–65 min old; 75 min means at least one run was missed. Rejected: the fetch timestamp, because it is refreshed on every run even when ADMIE has no new hour. |
| D08 | Commit messages carry Athens time | The runner's clock is UTC, so commits read "03:05" for a 06:05 run. |
| D09 | The accent colour is **amber** (`#fbbf24`, Tailwind `amber-400`) *(planned, phase 3)* | Follows BigHydro D23, one accent per dashboard; BESS emerald, Gas-Power blue, Flows cyan and BigHydro violet are taken, and the current green is effectively emerald. Amber suits a live page. Consequences: the *Delayed* and *Historical* pill states move to orange so they do not read as the accent, and the imports series colour (`#ffc000`) is reviewed during the port. |
| D10 | English by default with a Greek toggle; the choice is stored under the shared key `kp_lang` *(planned, phase 3)* | Follows BigHydro D24: all dashboards share one origin, so a visitor's language follows them across the hub. |
| D11 | Documentation starts lean: `DECISIONS`, `KNOWN_ISSUES` and `ROADMAP` now; `ARCHITECTURE`, `DATA_DICTIONARY` and `METHODS` after phase 2 | The data contract changes in phase 2, so describing it now would mean rewriting it. `METHODS` will also be the source text of the methodology modal. |
| D12 | No daylight-saving changes before 25 Oct 2026 | The owner is away that day. The day is recoverable: a manual run with start and end date re-fetches it, and records keep the maximum value, so a corrected, higher total replaces a low one. See K01. |
| D13 | Scope: this repository is handled in its own threads; the other dashboards and the shared shell are separate work | Keeps context clean, as for BigHydro (D21). |
